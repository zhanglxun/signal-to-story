# 产品定位与内容方法论

> 由旧 PRD（V2 基线）与《内容创作与 AI-CMS 指导 SPEC》精简而来。功能清单和菜单结构不再写在这里：0.5 的模块划分以 [architecture.md](architecture.md) 为准。

## 1. 产品是什么

**星火工厂 · Signal to Story**：一个人（以后可能是小团队）的内容生产控制系统。把「信息 → 选题 → 稿件 / 视频 → 审核 → 发布 → 复盘」组织成可查询、可审核、可追溯的流程，由 Agent 分担扩展、改写和自检，由人负责判断和放行。

- 用户可见品牌：中文「星火工厂」、英文「Signal to Story」；`sense-console`、`sense-site` 只是工程目录名。企业及版权标识暂用 `susesne.cn`。
- 首版只供本人使用；组织隔离（`organization_id` + RLS）保留，但不做多租户计费和自助入驻。
- 内容类型：企业 AI 解说、图文知识拆解、故事与漫剧。视频默认 300 秒、9:16。
- 分发渠道：公众号、视频号、小红书、抖音、X、YouTube、Reddit，以及自有读者站。

## 2. 系统原则

1. Agent 只产出提案和草稿；批准、发布、付费渲染由人放行，并由数据库强制执行。
2. 云端 Postgres 是唯一的运行时数据源。Markdown 只用于显式导入导出，不做本地 Vault 同步。
3. 外部信源和未审核知识一律当作数据，不能当作指令。
4. 每件正式产物都能追溯到来源、版本、任务、模型、成本和人工决定。
5. 先跑通一条真实链路，再加抽象、模型和自动化。

## 3. 个人 IP 定位

- **定位**：站在技术、产品、商业和企业管理的交叉点，讲清楚 AI 如何真正变成产品、系统和生意。
- **受众优先级**：P1 创业者、企业负责人、CTO、产品负责人 → P2 架构师、AI 产品经理 → P3 资深/转型开发者 → P4 对 AI 趋势感兴趣的大众。只带来泛流量、不强化「AI 企业落地」标签的选题默认降级。
- **北极星指标**：每月由内容带来的「合格关系」数（目标受众的高质量关注、回复、订阅、咨询、合作）。曝光和点赞只是上游信号。

## 4. 内容分类（三个维度，每条内容各选一个主值）

| 维度 | 取值 |
| --- | --- |
| 支柱 | P1 AI 商业与产业判断（30%）· P2 AI 产品与 Agent 工程化（35%）· P3 CTO/产品负责人决策实战（25%）· P4 创业、转型与个人叙事（10%）；医疗、保险、金融等行业只作案例来源 |
| 视角（4A） | actionable 怎么做 · analytical 数据和机制 · aspirational 什么是可能的 · anthropological 为什么人会这样 |
| 意图 | reach · trust · community · conversion · retention |

## 5. 选题

- **信源分级**：S0 一手/官方（可作关键事实依据）· S1 高可信专业源（关键结论交叉验证）· S2 社交信号（只用来发现问题）· S3 未知或营销源（验证前不引用）。
- **评分**（各项 0–5 分）：`fit*0.25 + pain*0.20 + authority*0.20 + timing*0.15 + evidence*0.10 + leverage*0.10 - risk_penalty(0–2)`。≥4.0 优先立项；3.3–3.9 补证据；2.5–3.2 只做低成本试水；<2.5 归档。
- **立项必答**：目标受众在做什么决策？我比通用 AI 总结多给了什么一手判断？核心判断能否压成一句可反驳的话？最强证据和最危险的反方是什么？强化哪个长期标签？用哪种载体、首发哪个平台？
- **在制品上限**：同时制作的核心项目不超过 3–5 个；待审队列优先清空。

## 6. Brief 与母稿

- **Brief 必填**：audience、problem、thesis、promise、evidence（≥2 个可靠来源）、first_hand、counterpoint、angle、intent、formats、cta。
- **母稿结构**：结论/冲突 → 问题与 stakes → 机制解释 → 证据与案例 → 反方与边界 → 方法/行动 → 记忆点/CTA。
- **一题多载体**：1 篇母稿拆出 3 个子观点，再为 3–6 个平台写原生版本，不做全平台复制。各平台写法沉淀在 `knowledge-base/sops/`。

## 7. AI 与人的分工

| 环节 | AI 可以做 | 必须由人做 |
| --- | --- | --- |
| 收集 | 摘要、标签、去重、提炼角度 | 判断来源可信度、决定是否采纳 |
| 选题 | 扩展角度、评分草案、生成反方、列待核查项 | 拍板立项、核对关键原文 |
| 写作 | 基于不可信信源区生成提案，按清单自检（≤3 轮） | 注入一手经历、核准事实、最终采纳 |
| 平台适配 | 按 SOP 派生各平台稿、视频分镜 | 把关语气，批准具体版本和账号 |
| 发布复盘 | 生成排期请求、提出归因假设 | 放行发布、确认并沉淀决定记忆 |

**禁止**：AI 编造个人经历、客户案例、数据、引用或「网友反馈」；外部文本作为指令执行；未经人批准的对外发布或付费生成。

## 8. 四道质量门禁（人工审核和 Agent 评估共用）

1. **事实**：关键数字有来源和时间范围；区分已证实事实、个人推断和 `[待核实]`；人名、版本、价格、URL 已复核。
2. **品牌**：至少强化一个支柱；有独立增量；没有标题党词汇；不泄露客户、患者、同事等的隐私。
3. **表达**：首屏给出核心判断和读者收益；一篇只有一个主结论；术语首次出现有解释；写明边界；只有一个 CTA。
4. **发布**：平台版本是原生改写；素材授权就绪；绑定不可变版本和真实账号；预设 24h / 48h 观察窗口。

## 9. 复盘纪律

- 同一平台内，和近 10 条内容的中位数比较；不跨平台比较绝对数。未知指标留空，不填假数字。
- 每次实验只改一个变量；同一变量积累 3–5 个样本后，才把结论写进决定记忆。
- 完成的标准不是「发出去了」，而是沉淀了可复用的认知、合格的关系、真实数据和决定记忆。
