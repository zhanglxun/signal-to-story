第 2 轮（MVP 精简版）。表名下蓝色框是对你第 1 轮意见的答复；划线的字段是 MVP 要删除的，红色标签写了它的去向；表末紫色字段是 MVP 新增的。完整说明见 docs/database.md 第 2～7 节和 9.1。
逐字段确认。每个字段标「可以 / 要改 / 有疑问」，要改或有疑问的请在备注里写清楚；表级意见写在表名下面的备注框。 类型、键、约束都是从仓库全部迁移在 PGlite 上实际建库后读出来的，不是手抄；只有「用途说明」是人写的。 标「退役 / 不上线」的表不必逐字段看：表名下点「确认移除」，整张表就收起，字段计为已审；点「要保留」再写明保留哪些字段。
标 草案 的是 DB2～DB5 计划新建的表或新增的字段，还没写进迁移，类型以审计结论为准。

审计标记保存在本浏览器的 localStorage（键 sts-schema-audit-v1），重新生成本页不会丢；导出的 JSON 或 .md 交回给我即可按结论改迁移。
