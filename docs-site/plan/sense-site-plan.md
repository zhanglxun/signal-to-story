# sense-site 建设计划

日期：2026-10-27。状态：规划待确认，尚未开工。本轮仅建立文档及目录说明；无应用代码、数据库迁移或线上变更。

用户已确定：根目录独立项目名 sense-site；沿用后台 UI 框架与组件；读取现有数据库；游客可读基础内容；先规划再建设。

## 拟确认的首版方案

采用 [PRD](../design/sense-site-PRD.md) 与 [SPEC](../spec/sense-site-SPEC.md)：独立 Vite 前端、同一 Supabase、独立站点发布快照和读者权限。首版支持公开/注册可读两级访问、收藏、专题、资源；收费会员后置。首版 SPA 的 SEO 限制已列出，如搜索收录为首发硬要求则需先调整渲染方案。

## 建设阶段

| 阶段 | 工作与交付 | 验收依据 |
| --- | --- | --- |
| P0 规划确认（当前） | 确认页面、公开数据边界、注册范围及 SEO 优先级 | 用户确认本计划后进入 P1 |
| P1 工程与数据契约 | 建立 sense-site，匹配控制台组件/主题与版本；核对最新官方 Supabase 文档；拟定表、RLS、事务及最小公开字段 | 两个工程独立 typecheck/build；权限和接口审阅完成 |
| P2 发布与匿名读取 | 迁移和索引、站点发布/下线事务、控制台站点发布页、首页/探索/文章 | 人工批准版本可上线；anon 可读基础内容，不能读内部稿件；下线生效 |
| P3 注册与内容组织 | 注册/邮箱确认/恢复密码、注册正文、收藏、专题与资源授权 | 两个读者账号隔离；未登录请求拿不到受限正文；下载鉴权通过 |
| P4 完整验证与部署交接 | 手机桌面 E2E、授权回归、部署配置、路由回退及回调配置说明 | 真实数据库读写链路验收、无假发布和假指标、域名部署后复验 |
| P5 商业化（后续独立确认） | 会员权益、支付/退款、到期撤权、订阅通知、SEO 增强 | 独立商业化需求及安全验收后开放 |

依赖按顺序推进，不把静态页面完成当作数据库链路完成。实现与验证在开发/隔离测试环境开展，迁移部署前评估生产权限影响；保留现有组织 RLS。若云端工具权限仍受限，记录阻塞，不能将本地或模拟结果标为线上验收通过。

```text

│   └── supabase/              # 统一数据库迁移与 SQL 验收
├── sense-site/                # 独立读者前端
│   ├── README.md              # 当前仅规划入口

│   │   ├── components/ui/     # 按需沿用既有基础组件
│   │   ├── components/site/   # 卡片、阅读、导航
│   │   ├── pages/
│   │   ├── services/
```

## 验证计划

- 代码阶段：sense-site 运行 typecheck、lint、test、build；控制台有改动时执行同样四项检查。
- 数据库：事务回滚测试覆盖 anon、注册用户 A/B、编辑员、审核员/发布员、不同组织；覆盖直接 Data API、正文表/关联查询、过期/猜测资源路径、发布后改稿、下线、旧版本、会员未实现入口。
- E2E：人工审核后站点发布 → 无痕游客阅读 → 注册确认后阅读受限内容 → 收藏 → 退出 → 下线后不可读。只能使用隔离测试组织和真实可清理的数据；Agent 仅在回滚或隔离测试中模拟人工门禁。
- 内容展示：清洗恶意 Markdown、禁用危险链接、个人缓存清理、空/错/加载状态、移动端与键盘可用性。
- 部署：独立构建目录、生产 URL、SPA 回退、Auth 回调白名单、HTTPS 注册流程；不把敏感正文打入静态包或公共缓存。

## 已知依赖与待确认默认值

默认只服务一个明确配置的站点及所属组织，预留 site_id 做隔离；不做多租户建站平台。公开网址和首批正式内容在部署阶段提供；开发可以用标记明确的隔离测试数据。注册复用现有 Supabase Auth，但读者不自动加入组织。开发前核查现有自注册设置和邮件发送配置，不能为站点注册改坏控制台登录。

计划确认前不安装依赖、不创建应用脚手架、不开放数据库权限、不部署。确认后按 P1–P4 建设，不要求用户重复确认普通实现细节。
