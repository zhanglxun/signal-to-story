# Signal to Story Console 菜单结构规划（讨论稿）

> 讨论稿，不是最终决定。本轮先只谈**流程和菜单**，表结构留到流程敲定后再单独设计。

---

## 0. 一句话总结

Console 是一条内容生产流水线，菜单是这条流水线上的几个"站点"，不是几个互相独立的系统。

```text
线索/灵感  →   选题    →  内容/脚本  →  分镜和素材   →   执行任务    →  发布效果
(哪些事      (值不值得    (写什么、     (视频工厂：      (谁在跑、      (发出去
 值得关注)    做)         怎么写)      拆镜头/配音/     跑到哪/       效果如何)
                                      配图/生成视频)    花了多少钱)
```

---

## 1. 不重新讨论的约束（来自 CLAUDE.md / SPEC）

- Console 只做控制面，不在浏览器里跑长任务、不持有 Provider Key。
- 菜单最多两层。
- 不先建空菜单——每个二级菜单背后要有真实要做的事，不是先摆位置。
- `video-factory/` 是当前唯一跑通的执行引擎，本机 Python 工程，不是 Console 内置能力。

## 2. 菜单树

```text
驾驶舱                                                    [现状]

内容生产                                                  [分组，不占路由]
├─ 选题                    流水线第 1-2 站：线索直接并入选题页的筛选态，
│                          不单开"情报 Inbox"
├─ 内容工作室               流水线第 3 站：母稿/脚本/审核
│                          [规划，等 Obsidian 导入做完再建]
├─ 视频工厂                 流水线第 4 站：对接 video-factory，
│                          拆分镜、配音、配图、AI 视频生成       [近期]
├─ 任务中心                 横切视图：不管哪一站在跑什么任务，
│                          正在执行/失败/重试的都在这看
└─ 资产库                   流水线产出的图片/音频/视频/成片，
                           统一存放、可复用

发布与复盘                                                [规划，等有真实发布需求再建]

系统管理                                                  [分组，不占路由]
├─ 组织与账号                                              [现状]
├─ 角色管理                                                [现状]
└─ 集成与外部端             体检面板：Obsidian 有没有连上、
                           AI 调用配没配好、上次有没有报错      [近期]
```

---

## 3. 各模块一句话说明

- **选题**：把"值不值得做"这件事管起来，线索和选题合并成一个页面，按状态筛选。
- **内容工作室**：管母稿和脚本改到哪一步、谁在审，正文主编辑端仍是 Obsidian。
- **视频工厂**：直接对接你已经跑通的 `video-factory`（`video_plan.json` 里的 `meta / character_refs / shots`），把分镜拆解、配音试听、AI 视频重抽这些操作从命令行搬到网页上。
- **任务中心**：不属于流水线的某一站，是横着汇总"正在跑的活儿"——不管是内容工作室在跑 AI 分析，还是视频工厂在跑万相生成。
- **资产库**：所有产出物（图片/音频/视频片段/成片）的统一仓库，不归到某个项目下才能看到。
- **集成与外部端**：纯状态展示，不涉及具体密钥——Obsidian 同步状态、AI 调用健康状态。密钥始终留在服务端。

---

## 4. 一个需要留意的点：视频工厂的 AI 调用方式

`video-mvp-task-plan.md` 里写的"网页端接入 Qwen3.7-Max"，如果做成浏览器直接调用 DashScope/Qwen API，会把 Key 暴露到前端，违反硬边界。

建议：网页点"智能拆解分镜"时，只调用一个 Supabase Edge Function，由它持有 Key、调用模型、把结果写回；真正耗时的配音/视频生成/合成，继续留在本机 `video-factory/` 里跑，网页只创建任务记录、看状态，不在浏览器里干等。

这个点是否认可，会影响后面 `video-mvp-task-plan.md` 任务 2 要不要改。
