# 星火工厂文字内容标准流程 v1

更新时间：2026-10-06。首个样例：光遗传学获诺奖。当前交付模式：真实信源与稿件入库，发布环节先演练，正式审核和发布由人工完成。

## 后续任务方向

最终形态扩展为多设备、多入口的个人内容助手，见 [任务路线图](personal-content-agent-roadmap.md)。IM 收录、云端自动制作、聊天审核、授权后发布和自动复盘按 M0–M4 推进；当前人工流程继续适用，不能将目标能力当作已上线能力。

## 每日协作约定

用户给题时，直接核查并制作；Agent 主动检索时，每批最多 3 个候选，列出事件日期、原始来源、建议角度、适合平台与事实风险，由用户选定。用户确认选题不等于批准最终正文。

| 阶段 | 输入 → 产物 | 通过标准 / 下一步 |
| --- | --- | --- |
| 采集 | 链接或口述 → 信息记录 | 纠正术语；核对日期；至少两家可靠来源验证关键事实；保留引用 |
| 选题 | 信息记录 → 选题卡 | 受众、立意、形式、禁忌、大纲明确；来源 ID 连通 |
| 立项 | 选题 → 云端项目 Brief | 来源 URL、核查备注、大纲与禁忌完整带入；检查是否已有项目 |
| 创作 | Brief → 母稿、X 稿、公众号稿 | 分平台表达；注明事实/假设/解读；云端保存版本 |
| 预审与终审 | 稿件 → 核查表、审核事件 | Agent 做事实预审并提审，人类审核具体平台及版本；改稿重新审核 |
| 演练 | 已保存稿件 → Markdown/JSON 交接包 | 明确未发布、待审核和账号缺口；不生成假业务数据 |
| 发布计划 | 已批准平台版本 + 真实账号 → 计划 | 平台匹配、绑定版本；没有授权时只导出人工发布 |
| 发布回填 | 真实发布 → URL + 实际时间 | 在平台确认成功后记录；不能用演练 URL 代替 |
| 复盘 | 实际发布后 24/48 小时 → 指标快照 | 保留数据来源、观察时间、口径、结论与下次实验；未知留空 |
| 流程改进 | 断点 → 修复 + 验证证据 | 每轮只沉淀实际有效的操作到技能与模板 |

## 渠道、账号和发布计划

- 一个具体账号登记一次；同一平台多个账号各自登记，名称与主页对应真实身份。登记不表示自动发布授权。
- 同一选题拥有不同平台稿件，各自审核；X 先试发，公众号随后独立排期。不能将 X 的审核状态冒用给公众号。
- 发布计划绑定账号、稿件和不可变版本。改稿后旧计划不能继续回填发布，需要取消重排。
- 记录实际发布时间后，系统展示 24 / 48 小时复盘时间。当前指标由人工回填，尚未接入平台后台自动采集。
- 未提供真实账号时保留配置缺口，不登记看似真实的占位账号。演练只产生交接文件与测试报告。

## 首轮沉淀资源

真实来源卡、术语与事实核查表、选题卡、完整 Brief、母稿、X 短帖、公众号文稿、历史版本、人工审核待办、发布演练包、复盘模板、回归测试及个人技能 `spark-text-pipeline`。

案例产物：`sense-console/content-runs/2026-10-06-optogenetics/`。个人技能位于 `~/.codex/skills/spark-text-pipeline/SKILL.md`，引用本项目流程，不包含账号秘密。

## 复盘模板

- 账号 / 平台 / 发布 URL / 稿件版本：
- 实际发布时间 / 本次观察时间 / 数据来源：
- 展示或阅读 / 点赞 / 收藏 / 评论（未知留空）：
- 观察到的评论主题（去除不必要的个人信息）：
- 标题、开头、篇幅或解释方式中，哪一项可能影响结果：
- 证据不足或不能归因的因素：
- 下一条只改变哪一个变量：

不要跨平台直接合计“阅读”与“展示”；没有曝光分母时不计算互动率。单条作品与两个时点只能形成初步观察，不能宣称证明了因果。
