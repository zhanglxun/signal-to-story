# 内容创作与 AI-CMS 指导 SPEC

> **V2.0 精简修订（2026-11-15）**：本文件已移除早期 Obsidian `4_Conttent` 本地目录树、Frontmatter 模板与历史同步规则，聚焦 **Signal to Story 个人 IP 定位、三维内容分类法、选题与写作标准、平台适配、四道质量门禁与数据复盘纪律**。这些规范的默认执行规则已同步沉淀为 `knowledge-base/` 默认种子，并与 Sense Agent Harness 的预检/评估清单对齐。
>
> 系统技术架构见 [总体系统架构 SPEC](Signal-to-Story总体架构-SPEC.md) · 产品需求见 [PRD V2 基线](../design/AI内容生产系统-PRD-v1.md)

## 1. 目标、非目标与六条核心原则

### 1.1 系统目标

1. **雷达**：持续发现 AI、产品、企业落地与行业变化。
2. **判断系统**：从噪声中识别值得投入的信号和选题。
3. **生产系统**：把经验、证据和观点转化为图文与视频内容资产。
4. **分发系统**：为 X、微信公众号、小红书、视频号及自有读者站生成原生版本。
5. **学习系统**：用发布数据和真实反馈修正定位、选题、表达与长期决定记忆（`decision_memories`）。
6. **商业系统**：把精准影响力转化为咨询、培训、课程、产品与合作机会。

### 1.2 非目标

- 不追求自动搬运、洗稿或无人工审核的“内容农场”。
- 不把粉丝量视为唯一目标；精准受众、专业信任和商业线索更重要。
- 不让平台热点反向绑架长期定位。
- 不维护脱离云端 Postgres 真相源的本地第二套内容状态。

### 1.3 六条核心原则

1. **一条内容只有一个核心判断。**
2. **证据先于表达，判断高于信息。**
3. **一个母题，多种载体；不是同一文案全平台复制。**
4. **AI 负责扩展、压缩、转换与结构化自检，人负责事实责任、核心判断、审美与最终放行。**
5. **所有正式稿件与版本保存在云端 Postgres，媒体资产存对象存储，支持标准 Markdown 显式导入导出。**
6. **所有发布都必须回流数据和经验，经验证后沉淀为可复用的知识条目或决定记忆。**

## 2. 个人 IP 定位

### 2.1 定位决策共识

| 共识 | 最终决策 |
| --- | --- |
| 不能做泛科技或纯工具教程 | 工具内容只做入口，不做身份标签 |
| 稀缺性来自技术、产品、商业和企业实战交叉 | 所有核心内容至少连接其中两个维度 |
| AI Agent / 企业落地兼具需求和专业壁垒 | 作为长期主赛道 |
| 技术负责人、产品负责人决策经验价值高 | 作为信任与变现支柱 |
| 医疗、保险、金融经验难复制 | 作为案例矿山和专业纵深，不把品牌锁死在单一行业 |
| 一人公司、创业和转型有传播力 | 作为人格化副线，不替代核心定位 |

### 2.2 定位表达

- **正式定位**：站在技术、产品、商业和企业管理的交叉点，讲清楚 AI 如何真正变成产品、系统和生意。
- **短 Bio**：
  > 18 年技术与产品实战｜前大型平台技术产品负责人
  > 研究 AI、Agent 与企业数字化
  > 拆解 AI 产品、技术架构与商业模式
- **视频/播客开场**：我不只追 AI 热点，我更关心它怎么落到业务、系统与 ROI。
- **目标认知标签**：“那个专门讲 AI 企业落地，而且技术、产品、商业都懂的人。”

### 2.3 目标受众优先级

| 层级 | 受众 | 核心问题 | 希望形成的行动 |
| --- | --- | --- | --- |
| `P1` | 创业者、企业负责人、CTO、产品负责人 | AI 是否值得做、从哪里做、ROI 和风险是什么 | 关注、转发给团队、咨询/培训 |
| `P2` | 架构师、技术经理、AI 产品经理 | Agent / RAG / Workflow / Eval 怎么设计和落地 | 收藏、订阅、参加课程/社群 |
| `P3` | 资深开发者、独立开发者、技术转型者 | 如何从“写代码”升级到做产品和决策 | 长期关注、购买工具/课程 |
| `P4` | 对 AI 商业和产业趋势感兴趣的大众 | 这次变化和自己有什么关系 | 互动、分享、进入深度内容 |

> **受众取舍**：如果一个选题只能带来泛流量，却不能强化“AI 企业落地 / 技术商业判断”的标签，默认降级处理。人格化内容可以拓宽关系，但不能连续占据主发布位。

### 2.4 内容价值阶梯

1. **热点与观点**：获得注意力。
2. **解释与拆解**：建立认知差异。
3. **方法与框架**：建立专业信任。
4. **案例与证据**：形成能力背书。
5. **咨询/培训/产品**：承接高价值需求。

## 3. 三维正交内容分类法

内容分类通过三个正交属性（支柱、表达视角、意图）在数据库字段与知识标签中表达，不靠多层嵌套分类目录混用标准。

### 3.1 维度 A：内容支柱——“1 + 3 + N”

- **1 个核心母题**：`AI × 企业 × 产品 × 商业`
- **3 个长期支柱 + 1 个人格副线**：

| code | 支柱 | 作用 | 典型选题 | 建议占比 |
| --- | --- | --- | --- | ---: |
| `P1` | AI 商业与产业判断 | 流量入口 | SaaS 会不会被 Agent 重构；大厂为何调整 AI 组织 | 30% |
| `P2` | AI 产品与 Agent 工程化 | 专业壁垒 | Agent 权限、Memory、RAG、Evaluation、HITL | 35% |
| `P3` | CTO / 产品负责人决策实战 | 信任与变现 | 重构决策、团队治理、复杂项目、ROI | 25% |
| `P4` | 创业、转型与个人叙事 | 人格连接 | 技术老兵转型、一人公司、真实成败复盘 | 10% |

- **N 个案例矿山**：医疗、妇幼健康、保险、金融、证券、SaaS、企业服务、出海、开发者工具和大厂战略，都作为具体支柱下的证据与案例支撑，而非并列的新赛道。

### 3.2 维度 B：表达视角——4A Framework

| angle | 回答的问题 | 适合的表达 | 例子 |
| --- | --- | --- | --- |
| `actionable` | 怎么做 | SOP、清单、框架、教程 | 企业 Agent 上线前的 12 项检查 |
| `analytical` | 数据和机制是什么 | 趋势、数字、拆解、对比 | 为什么 80% AI Demo 无法进入生产 |
| `aspirational` | 什么是可能的 | 个人故事、转型、教训、里程碑 | 18 年技术人如何重建 AI 能力栈 |
| `anthropological` | 为什么人会这样 | 悖论、心理、组织与权力 | 企业最难的不是模型，而是责任分配 |

优先组合：`analytical + actionable`（专业壁垒）、`aspirational + anthropological`（个人连接）、`analytical + anthropological`（高传播产业判断）。

### 3.3 维度 C：内容意图

| intent | 目标 | 常用 CTA |
| --- | --- | --- |
| `reach` | 新受众发现 | 关注、转发、参与讨论 |
| `trust` | 证明能力和判断 | 收藏、查看完整案例、订阅 |
| `community` | 建立关系和对话 | 评论经历、投票、提问 |
| `conversion` | 承接明确需求 | 下载清单、预约咨询、参加培训 |
| `retention` | 让老受众持续获得价值 | 系列追更、周报、专题导航 |

> 每条内容必须明确 1 个主支柱、1 个主视角、1 个主意图。

### 3.4 高互动样本的保留与禁止规则

- **保留**：真实经历或一手观察；开头清晰冲突、正文机制解释、结尾明确判断；长内容结构化、短内容单一记忆点；实用价值与情绪价值兼顾；用数据复盘。
- **禁止**：用无法核验的夸张数字制造焦虑；把相关性写成因果；机械使用“震惊”“99%的人不知道”“不看后悔”等模板化情绪钩子（已写入 `knowledge-base/brand-voice/default-brand-guide.md` 与 Harness 确定性预检规则）。

## 4. 内容生命周期、信源分级与选题评分

### 4.1 端到端业务流与 WIP 控制

```text
信源 (Source) → 线索 (Signal) → 去重聚类 → 候选选题 (Selection)
  → 立项 Brief (ContentProject) → 母稿与评估循环 (ContentDocument + Harness)
  → 人工终审 → 平台原生变体 → Mandate 审批 → 发布与 24/48h 指标快照 → 复盘与决策记忆
```

WIP 控制原则（避免“囤积式创作”）：同时处于立项制作（`draft` / 制作中）的核心项目不超过 3～5 个，待审核队列优先清零后再批量开启新项目。

### 4.2 信息源分级

| source_tier | 类型 | 示例 | 使用规则 |
| --- | --- | --- | --- |
| `S0` | 一手/官方 | 官方文档、财报、论文、访谈原片、亲历数据 | 可作为关键事实依据 |
| `S1` | 高可信专业源 | 权威媒体、资深从业者一手分析 | 关键结论尽量交叉验证 |
| `S2` | 社交信号源 | X 博主、社群讨论、评论区 | 用于发现问题，不直接当事实 |
| `S3` | 未知或营销源 | 聚合号、无出处截图、带强销售目的内容 | 只进待处理信息，验证前不引用 |

定向情报域：企业 AI 与 Agent 工程（RAG / Workflow / Eval / MCP / 权限 / Memory）、大厂 AI 战略与组织调整、ToB SaaS 与数字化、医疗/保险/金融 AI 案例、一人公司与 AI Native 出海。

### 4.3 热点与选题评分模型

- **时效分级**：`P0`（2 小时内拍板）、`P1`（24–72 小时窗口，24 小时内出 Brief）、`P2`（1–4 周专题）、`P3`（常青方法论）。
- **热点原则**：不抢“发生了什么”的第一时间，争取“这意味着什么、为什么、企业该怎么办”的第一判断。
- **6 维加权评分（0–5 分）**：

```text
base_score = fit*0.25 + pain*0.20 + authority*0.20
           + timing*0.15 + evidence*0.10 + leverage*0.10
final_score = base_score - risk_penalty   # risk_penalty ∈ [0, 2]
```

阈值决策：`>= 4.0` 优先立项；`3.3–3.9` 进入候选补证据；`2.5–3.2` 仅低成本格式试水；`< 2.5` 归档淘汰。

- **立项必答 6 问**：
  1. 目标受众是谁？正在做什么决策？
  2. 我比通用 AI 总结多提供了什么一手判断？
  3. 核心判断能否压缩成一句可反驳的话？
  4. 哪条证据最强（S0/S1）？哪条反方意见最危险？
  5. 做完后能强化哪个长期标签？
  6. 最适合哪种母稿形式与首发平台？

## 5. 从 Brief 到母稿与 AI 协作边界

### 5.1 Brief 最低标准

`audience`（具体角色情境）、`problem`（当前痛点）、`thesis`（可验证核心判断）、`promise`（读者收益）、`evidence`（至少 2 个可靠来源）、`first_hand`（一手观察/数据）、`counterpoint`（最强反方观点）、`angle`（4A 视角）、`intent`、`formats`（目标载体与平台）、`cta`（单一主行动）。

### 5.2 母稿默认结构

1. **结论/冲突**：开篇抛出最值得记住的核心判断。
2. **问题与 stakes**：为什么这件事现在值得关心。
3. **机制解释**：深入系统与商业逻辑，不只罗列现象。
4. **证据与案例**：数据、真实项目经验与可追溯来源。
5. **反方与边界**：在什么前提下结论不成立。
6. **方法/行动**：读者下一步可执行清单。
7. **记忆点/CTA**：收束为一句话与一个行动。

### 5.3 AI 协作红线

| 环节 | AI（Sense Agent Harness）可以做 | 必须由人类负责 |
| --- | --- | --- |
| 捕获与聚类 | 摘要、标签建议、去重、提炼潜在角度 | 确认来源可信度、决定是否采纳 |
| 选题与研究 | 角度扩展、评分草案、生成反方、列待核查清单 | 拍板立项、核对关键一手原文 |
| 写作与预检 | 基于 `<untrusted_source_data>` 生成提案、按只读 Evaluator 清单自检（≤3 轮） | 注入真实一手经历、核准事实、最终采纳 |
| 平台适配 | 依据母稿与平台 SOP 派生 X / 公众号 / 小红书 / 视频分镜草案 | 把关语气审美、批准具体版本与目标账号 |
| 发布与复盘 | 构建排期请求、基于指标快照提出归因假设 | Mandate 签名放行发布、确认并沉淀长期决定记忆 |

> **禁止事项**：AI 不得编造个人经历、客户案例、项目数据、引用或“网友反馈”；外部信源文本严禁作为指令执行；未获人类批准禁止任何对外发布或高额付费媒体生成。

## 6. 一题多载体与多平台原生适配

采用 **Hub-and-Spoke（1-3-5）** 模式：1 篇完整母稿（Hub）拆解出 3 个独立子观点，按需为最适合的 3～6 个平台生成原生版本，拒绝机械复制：

- **X（Twitter）**：开门见山给出反常识或强冲突判断，短段落推进；Thread 每条推动一层论证；关键数字必须附来源；关注高质量回复与书签收藏。
- **微信公众号**：注重叙事节奏、结构化小标题与金句卡片，兼顾手机端阅读呼吸感，结尾附明确延伸阅读或行动引导。
- **小红书**：适合清单、避坑、框架与对比故事；封面突出“问题 + 结果”；正文分 6–10 页卡片（每页单一信息单元），重收藏与搜索关键词。
- **视频号 / 短视频**：前 3 秒（Shot 001）必须直击视觉奇观或核心冲突，不做冗长自我介绍；遵循 Audio-First 旁白对齐，单观点 45–90 秒，案例拆解 2–5 分钟，画面以高信息密度架构图/数据卡/精简动态镜头为主。
- **自有读者站（`sense-site`）**：承接最完整、可长期检索与订阅的系统级长文、方法论专题与资源下载包。

每周基础节奏建议：1 个深度 Hub + 2 个分析/方法类拆解 + 1 个真实经历/案例 + 1 个互动/问答，有强信号时再响应热点；在形成稳定产能前，优先保证质量与复用率而非机械日更。

## 7. 四道质量门禁（与 Agent Harness 评估清单对齐）

在人工智能审核与 Agent Evaluator 评估阶段，共同遵循以下四道门禁：

1. **事实门禁**：所有关键数字标注来源与时间范围；区分新闻发生时间与报道时间；重要事实至少阅读过 S0/S1 原文；明确区分“已证实事实”与“个人推断”或 `[待核实]`；人名、模型版本、价格与 URL 经复核无幻觉。
2. **品牌门禁**：强化至少 1 个内容支柱；提供独立经验或框架增量；无低质标题党情绪词；不泄露客户、患者、公司、同事隐私及敏感信息；商业合作透明。
3. **表达门禁**：首屏明确核心判断与受众收益；单篇只有一个主结论；每段推动论证无冗余填充；首次出现的专业术语给出清晰解释；明确边界/反方条件；只有一个主 CTA。
4. **发布门禁**：平台版本为原生改写而非直接照搬；封面、标题、字幕、链接及素材授权就绪；严格绑定不可变 `revision` 与真实账号；已预设 24h / 48h 指标观察窗口。

## 8. 数据指标、实验纪律与首批内容系列

### 8.1 北极星指标与分层口径

- **北极星指标**：**每月由内容产生的“合格关系”数量**（目标受众的高质量关注、回复、订阅、私信、转介绍、咨询与合作机会）。曝光和点赞只是上游信号。
- **严禁跨平台硬比较绝对数**：使用同平台近 10 条内容的中位数、同支柱与同格式相对基线评估；未知指标在系统中保持 `null`（不填假数字），无曝光分母时不计算互动率。

### 8.2 单变量实验纪律与复盘

- 每个实验每次只变更**一个主变量**（如标题钩子、开头方式、篇幅或视觉卡片）；
- 不用单条爆款证明方法论万能，也不因单条低迷否定赛道；连续 3～5 个同变量样本后，再决定是否将结论通过审核/复盘页一键写入 `decision_memories` 作为长期约束规则。

### 8.3 首批重点内容系列方向

1. **系列 A：企业 AI 为什么总停在 Demo**（RAG/Workflow/Agent 选型、权限与审计硬骨头、企业 ROI 核算）。
2. **系列 B：AI Native 产品经理**（Intent/Context/Memory/HITL/Eval 设计、MCP 边界）。
3. **系列 C：技术负责人的复杂决策**（系统演进 vs 重写、AI 时代工程团队治理）。
4. **系列 D：行业案例矿山**（医疗、保险、金融场景中 AI 的权限、合规与真实落地）。
5. **系列 E：技术老兵的 AI 转型**（18 年实战经验重构、一人公司杠杆与可复利知识资产）。
