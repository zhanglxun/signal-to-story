# 综合判断:Agent 是否已进入"自循环、持续工作"阶段

> **归档状态（2026-11-15）**：本文件核心判断已转化为 Signal to Story V2 架构决策并落地于 P1/P1.5（见 [V2 统一架构规划](../plan/v2-unified-architecture-plan.md) 与 [agent-harness.md](../../sense-console/docs/agent-harness.md)），本文件保留作理论溯源归档。
> 第二版,2026-11-05。第一版只基于官方工程文章和 DeepSeek 原型仓库;这一版补入了 DeepSeek 长文、卡兹克两篇长文与 Agent-Autoloop README、0xwhrrari 长文(均经用户 Notion 页附件,见各笔记的取得方式)。
> 吴恩达课程、知识猫评论、OpenAI 三篇**仍未读到**,相关结论标为"待验证"。

## 结论

**DeepSeek 与卡兹克确实在讲同一件事,而且是明确的接力关系;Anthropic 的文章讲的是它们之下的另一层。**吴恩达那一条目前没有一手证据,不并入结论。

1. **DeepSeek ↔ 卡兹克**:卡兹克开篇直接引用 DeepSeek 的"多任务上限取决于人的注意力",并说自己是对它的回应(见 [08](sources/08-卡兹克-agent自动化系统与autoloop.md))。两者共同的命题是:**把任务的发起点从人身上拿掉,由环境事件触发 agent,人只在必须决策时介入。**
2. **但两者给出的是相反的实现立场**,不是同一套架构的两种说法(见下表)。
3. **Anthropic / 0xwhrrari / Google 讲的是单个任务内部**:怎样跨会话保持状态、怎样独立验证、怎样防止"过早宣布完成"。这是 DeepSeek 和卡兹克都默认已经有的那一层。

所以"进入自循环阶段"更准确的说法是:**瓶颈已从模型能力转向外围系统——触发、授权、状态、验证、人的注意力。**这个判断有三个独立来源互相印证,较可靠;但它们都来自软件工程场景。

## 两种实现立场的对比(这是这一版新增的最大发现)

| 议题 | DeepSeek | 卡兹克 / Autoloop |
| --- | --- | --- |
| 路由由谁做 | LLM 会话(Router),用较轻模型;代码只做前置过滤和订阅直通 | **确定性内核 + `rules.json`**,内核约 1600 行,不联网,同输入同输出 |
| Agent 在哪跑 | 云端无状态容器,端点装 daemon | 本机,靠长轮询拉活,不暴露公网 |
| 为什么 | 常在线、不依赖单机 | 凭证与权限不想在云上复制 |
| 谁和人说话 | 只有 Router,Worker 不直接发言 | 所有 agent 走同一个通道(飞书助理) |
| 噪声控制 | 每条回复 ≤100 字;安静为默认 | 规则里 `tell: needed`;脚本先过滤、能不叫醒模型就不叫醒 |
| 安全 | 作者列为**开放问题**,承认提示注入可能接管所有端点 | 只读审查者、全新虚拟机、**指令数据分离**、**跳数上限 8 层** |
| 成熟度 | 原型,自称与文章不完全一致 | 作者自称 1.0.0、可能有 bug、仅 macOS/Linux |

## 跨来源共同模式(≥2 个已核实来源)

1. **人的注意力是预算。**DeepSeek 的"尽量少占注意力"(哲学文档)、卡兹克的"只推需要拍板的事"、Claude Code 的按风险分级审批。
2. **只在必须时打扰人**,并明确列出"必须问"的类别。卡兹克的清单:删数据、停服、花钱、对外发消息、改产品方向、新建或轮换密钥、改权限。
3. **授权与执行分离,agent 不能自己放行。**DeepSeek 的 Mandate;卡兹克的"agent 提交 PR 就结束,不能自己上线";Claude Code 的"agent 的批准不算人的批准";0xwhrrari 的"模型建议 → 策略检查 → 工具执行"。
4. **做事的和审的分离。**Anthropic 的 evaluator;卡兹克用不同模型审查,且审查者只读;Claude Code 的验证 agent 投票。
5. **状态外置,可回溯,可恢复。**`feature_list.json`+进度文件;DeepSeek 的 Ticket/Thread;Autoloop 的追加式账本与"挂起零消耗"。
6. **幂等与去重。**DeepSeek 的"同一 Trigger 只产生一个 Ticket";卡兹克的统一去重与事件溯源。
7. **循环必须有上限。**卡兹克的审查 3 轮、跳数 8 层;0xwhrrari 的"每个循环有重试上限和预算";Claude Code 的"每条发现必须修复或附理由关闭"。
8. **记住人做过的决定,不重复问。**卡兹克的"卡兹克定的事 / 定了不做的事";DeepSeek 的 Policy 版本化。
9. **能用确定性代码就不用模型。**DeepSeek 的 Fast Path;Autoloop 的内核与"脚本先看一眼、没事不叫醒模型"。
10. **harness 是随模型变化的假设。**Anthropic 的"每次换新模型要删减组件"。

## 与第一版相比,被修正或加强的判断

- **加强**:"瓶颈在外围系统"。现在有两个独立团队(DeepSeek 内部系统、卡兹克的个人系统)各自走到同一结论,并且都给了运行数据(见各自的自报数字)。
- **修正**:第一版把 DeepSeek 原型的"无审批执行命令"当成它的一个特点。读了长文后看到,作者**自己把安全列为开放问题**,并明确说这套设计隐含"云与端点互信"的假设。所以不应把它当成可照抄的权限模型。
- **新增**:卡兹克系统里最值得借的不是中台本身,而是**一组很具体的防失控机制**:跳数熔断、挂起零消耗、指令数据分离、审查者只读、决定记忆。这些比"Router/Worker"更小、更可移植。
- **新增**:两个来源的**路由方式相反**(LLM 路由 vs 规则路由)。这是一个真实的设计分歧,不是术语差异。对个人规模的系统,规则路由更便宜、更可审计;DeepSeek 自己的实验也只说"当前团队规模下单个 Router 够用"。

## 证据质量

- 全部"实验"和"统计"都是作者自报:DeepSeek 的消融实验用合成负载并自称"仅供参考";卡兹克的 298 个 PR、333 条问题等未经独立验证;Claude Code 的 16%→54% 同理。
- 卡兹克称"最多审 3 轮"借鉴自 Anthropic 文章,我读到的摘要里没有这个数字,出处待查。
- 吴恩达条目只有视频标题和时间轴,没有内容。Notion 页自己也注明"非一手官方课程页"。
- 这些材料几乎都在讲**代码**。代码有测试可跑,内容"是否合格"没有等价物。0xwhrrari 对研究类产物只写了一行"来源核对+矛盾核对"。**迁移到内容生产的有效性,目前没有任何来源给出证据。**
