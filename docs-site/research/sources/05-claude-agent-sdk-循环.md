- 核实状态:已核实(通过抓取摘要)

## 循环:收集上下文 → 行动 → 验证 → 重复

**收集上下文**
- 代理式搜索:信息存在文件系统,agent 用 `grep`、`tail` 等按需加载;**文件夹结构本身就是上下文工程**。语义检索更快但更不准、更难维护、更不透明,先不用。
- 子 agent:并行,各有独立上下文,只回传相关结果。
- 压缩:接近上限时总结早期消息。

**行动**:工具(要精心设计,占用上下文并强烈影响 agent 的选择)、bash/脚本、代码生成(精确可复用)、MCP(标准化外部集成,处理认证)。

**验证**
- 基于规则:lint 与明确检查,说明哪条规则失败及原因。
- 视觉反馈:渲染结果截图,检查布局、样式、层级。
- LLM 作评委:第二个模型按模糊标准评分;不够稳健,增加延迟和成本,只在值得时用。

## 设计要点

给 agent 一台"电脑";主要动作做成工具并节省上下文;先简单后复杂;通过复盘失败来改进("它有没有合适的工具和信息");用代表真实使用的评测集测试。
