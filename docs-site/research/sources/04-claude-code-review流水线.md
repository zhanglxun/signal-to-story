# Claude Code 团队的代码审查流水线

- 来源:https://claude.dev/blog/solving-code-review-at-anthropic/
- 抓取日期:2026-11-05
- 核实状态:已核实(通过抓取摘要)。用户清单里的 X 转述帖未核实。

## 流水线

1. **提交前自验证**:运行测试、构建、lint 并展示输出,而不是只"声称完成";用新上下文的子 agent 审 diff。反复出现的问题**在源头修**:写进 skill、lint 规则或指令文件。`CLAUDE.md` 写项目约定;`REVIEW.md` 由代码负责人写,说明该区域"失败长什么样"、限制吹毛求疵、要求给出文件与行号证据。
2. **每个 PR 的多 agent 审查**:多个 agent 并行找 bug,对照整个仓库和 PR 意图;另一组**验证 agent 对每条发现投票**,足够多认可才发布。风格、诊断、清理类发现被丢弃(团队 A/B 测试过这些过滤器)。输出分 Important / Nit / Pre-existing,避免把历史问题算到作者头上。每条发现必须修复或附理由关闭。报告:有实质评论的内部 PR 占比从 16% 升到 54%。
3. **安全审查(可阻断合并)**:独立的自动安全检查,未关闭的发现阻断合并。
4. **必过 CI(可阻断)**:lint、类型检查、跨平台测试、构建;PR 模板要求写明如何测试、如何回滚。
5. **按风险分级的人类审批**

| 风险 | 示例 | 人类审批 |
| --- | --- | --- |
| 低 | 文档、文案、带开关的增量改动 | 自动检查通过即可,无需人 |
| 中 | 普通产品改动,敏感区域(缓存、自动更新、系统提示) | 1 人 |
| 高 | 最高风险代码与必须双人的路径 | 2 人 |

   分级由分类器按**改动**而非作者决定;另一分类器可强制要求人审;CI 工作流文件和负责人列出的敏感路径至少 1 人。只有可信作者才能走轻量档;**agent 的批准不算人的批准**;提示 agent 写代码的那个人算必需审阅者;审批绑定具体 commit,新 commit 需重新审批。
6. **合并与发布**:合并队列对最新 main 重跑检查;功能带开关、先内部使用;发布先走 `latest` 再到 `stable`;开关无需部署即可关闭,坏构建回滚。

## 度量

关注"每个 PR 的人类审批数"和"人类耗时",以回滚率和事故率为护栏。原文称 6–9 月合并 PR 数翻倍以上,回滚占比下降超过 40%。
