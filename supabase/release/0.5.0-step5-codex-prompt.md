# 给 Codex 的提示词：执行 0.5.0 第 5 批（最终批次）

> 用法：把下面「提示词」整段发给 Codex。执行手册在 [README.md](README.md) 的「0.5.0 第 5 批」一节，提示词只是把手册按顺序交代清楚，不重复其中的 SQL。

## 提示词

```text
你在仓库 signal-to-story 的 0.5.0 分支上工作。任务：把数据库最终批次 supabase/release/0.5.0-step5.sql 推到线上 Supabase，并部署 0.5 控制台与读者站。严格按 supabase/release/README.md 中「0.5.0 第 5 批」一节的步骤 0～8 执行，不要跳步，也不要自行改 SQL。

规则：
1. 不要在输出、日志、提交里打印任何密钥、数据库连接串、项目 ID、节点令牌。
2. 先 git pull 到包含 supabase/release/0.5.0-step5.sql 的提交，在本地跑步骤 0 的门禁命令；有失败就停下汇报，不要上线。
3. 步骤 1 必须先停掉所有 worker（npm run worker:agent、视频 worker），等租约过期。
4. 步骤 2 必须先备份（db dump 或 Table Editor 导出 CSV），备份放在仓库外，不要提交。没有完成备份不要执行脚本。
5. 步骤 3 只读预检：任一结果与注释里的期望值不符，就停止，把结果原样发回来。
6. 步骤 4 整份执行 0.5.0-step5.sql，一次运行；报错即已整体回滚，不要分段重跑，不要手工修补，把报错原文发回来。成功后记下 backfill_v1 (final) 通知。
7. 步骤 5 跑核对 SQL，把全部结果原样发回来。
8. 核对通过后再做步骤 6（构建并部署 sense-console、sense-site；读者站 VITE_SITE_DEMO 必须为空）和步骤 7（用新代码重启 agent worker 与视频 worker）。
9. 不执行 supabase db push，不修改函数环境变量，不删除存储桶，不推送任何分支。

最后用一张表汇报：每一步的结果（通过 / 停止）、预检与核对 SQL 的原始输出、backfill_v1 (final) 通知、前端部署地址是否已更新、worker 是否已用新代码启动。
```
